# Model Repository Guide

The Triton model store (`model_repository/`) defines the executable inference graph of the system. Each subdirectory describes a specialized model backend — its configuration, instance placement, and I/O tensor contracts — and how those backends compose into a single inference pipeline.

For system-level design context, see [ARCHITECTURE.md](ARCHITECTURE.md).

---

## Model Inventory

| Model | Backend | Instance Group | BLS execution role | Purpose |
|-------|---------|---------------|-------------------|---------|
| `bls_orchestrator` | `python` | 1× GPU | Entry point | Orchestrates the RAG DAG |
| `yolo_onnx` | `onnxruntime_onnx` | 1× GPU | Stage 1 | Vision guardrail |
| `embedding_onnx` | `onnxruntime_onnx` | 1× GPU | Not used (current implementation) | Embedding export (alternate path) |
| `reranker_py` | `python` | 1× GPU | Stage 4 | Cross-encoder reranking |
| `llm_vllm` | `vllm` | 1× MODEL | Stage 5 | Text generation |

---

## BLS Call Graph

```
Client
   │
   ▼
bls_orchestrator
  ├── InferenceRequest("yolo_onnx")      → stage 1: vision
  ├── SentenceTransformer.encode()        → stage 2: embed (in-process)
  ├── QdrantClient.query_points()         → stage 3: retrieve (external)
  ├── InferenceRequest("reranker_py")     → stage 4: rerank
  └── InferenceRequest("llm_vllm")        → stage 5: generate (decoupled)
```

## bls_orchestrator

**Backend:** `python`  
**Source:** `model_repository/bls_orchestrator/1/model.py`

### Inputs

| Name | Type | Shape | Description |
|------|------|-------|-------------|
| `query` | `TYPE_STRING` | `[-1]` | User text query (UTF-8) |
| `image` | `TYPE_FP32` | `[-1, 3, 640, 640]` | RGB image, CHW layout, normalized 0–1 |

### Outputs

| Name | Type | Shape | Description |
|------|------|-------|-------------|
| `response` | `TYPE_STRING` | `[-1]` | JSON string: `{"answer": "...", "debug": {...}}` |

### Configuration

- `max_batch_size: 0` — no dynamic batching at orchestrator level
- `instance_group: KIND_GPU, count: 1`

### Environment Variables

| Variable | Default | Used for |
|----------|---------|----------|
| `QDRANT_URL` | `http://qdrant-server:6333` | Qdrant client connection |
| `QDRANT_COLLECTION` | `technical_support` | Collection name |
| `EMBEDDING_MODEL_ID` | `sentence-transformers/all-MiniLM-L6-v2` | SentenceTransformer model |
| `EMBEDDING_DEVICE` | `cuda` | Embedder device |
| `LLM_MODEL_ID` | `Qwen/Qwen3-4B-Instruct-2507` | Chat tokenizer for prompt formatting |

Complete configuration reference will be provided in [docs/CONFIGURATION.md](CONFIGURATION.md) (Plan 02).

## embedding_onnx

**Platform:** `onnxruntime_onnx`  
**Artifact:** `model_repository/embedding_onnx/1/model.onnx` (generated by `scripts/export_embedding.py`)

## llm_vllm

**Backend:** `vllm`  
**Config:** `model_repository/llm_vllm/1/model.json`

### Representative model.json

```json
{
    "model": "Qwen/Qwen3-4B-Instruct-2507",
    "tensor_parallel_size": 1,
    "max_model_len": 8192,
    "gpu_memory_utilization": 0.85,
    "dtype": "auto",
    "max_num_seqs": 4,
    "trust_remote_code": true
}
```

Override the model by editing the `"model"` field or setting `LLM_MODEL_ID` in the environment (BLS tokenizer reads this; vLLM reads `model.json`).

### Inputs (vLLM backend convention)

| Name | Type | Description |
|------|------|-------------|
| `text_input` | `TYPE_STRING` | Chat-formatted prompt |
| `sampling_parameters` | `TYPE_STRING` | JSON: `{"temperature": 0.1, "max_tokens": 512}` |
| `stream` | `TYPE_BOOL` | `false` for single response |

### Outputs

| Name | Type | Description |
|------|------|-------------|
| `text_output` | `TYPE_STRING` | Generated text (decoupled stream) |

### Configuration

- `instance_group: KIND_MODEL, count: 1` — vLLM manages its own GPU allocation
- Invoked with `decoupled=True` from BLS

## Substituting a Larger LLM

1. Update `LLM_MODEL_ID` in `.env` (BLS tokenizer)
2. Update `"model"` in `model_repository/llm_vllm/1/model.json` (vLLM weights)
3. Adjust `max_model_len`, `gpu_memory_utilization`, and optionally `tensor_parallel_size`
4. Restart Triton: `docker compose up -d --build triton`

Example for Qwen3-30B MoE on a datacenter GPU:

```json
{
    "model": "Qwen/Qwen3-30B-A3B-Instruct-2507",
    "tensor_parallel_size": 1,
    "max_model_len": 32768,
    "gpu_memory_utilization": 0.90,
    "dtype": "auto",
    "max_num_seqs": 2,
    "trust_remote_code": true
}
```

No BLS code changes are required — orchestration remains independent from the underlying LLM implementation, so only configuration and the vLLM backend need to change.
